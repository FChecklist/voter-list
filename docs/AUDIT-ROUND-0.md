# AUDIT ROUND 0: the product as it stood on 11 Nov 2026 against the owner's nine requirements (13 Nov 2026)

Auditor: the builder (this is a gap check, **not** the Rule 7c certification; the independent audits start at round 1).
Baseline checked on 13 Nov 2026: `bun run typecheck` clean, `bun test --isolate` = 140 pass / 0 fail. Nothing deployed. `wrangler.toml` database_id is a placeholder.

Severity: **S1** blocks the owner's design, **S2** serious gap, **S3** polish.

## Verdict in one line
The engine underneath (signed audit chain, atomic guards, masking, import, checks, immutable versions) is strong and is kept. The **product shape on top of it conflicts with the owner's design** in five places (R1, R2, R3, R4, R6) and misses two (R5 public portal, R8 India practice details). It is a rebuild of the middle and the screen, not of the foundation.

## Other findings (not tied to one requirement)

1. **Dead weight after the redesign.** Old tabs, the separate member page, per-event freeze and claims code would sit unused. Plan: remove them from the shipped code (git history keeps them), keep only the foundations. *S2*
2. **Legacy tables.** Migrations 0001 to 0004 stay as they are (nothing deployed, but the owner asked for additive migrations). New migration 0005 adds the new tables and **rebuilds only `memberships`** to allow the `host` role (data is copied across). Old tables stay in place, unused, and are listed in the deploy plan as "legacy, harmless". *S3*
3. **Price slot.** "Save Version 1" order logic exists in test mode only; live Razorpay is not wired. The owner's rule (payments only through IT SERVICES BY RAJAT AGARWAL on Razorpay, no paid step without asking) is respected. Keep the slot, keep it off by default. *S3*
4. **D1 and browser unverified.** `changes()` inside a batch, `UPDATE ... FROM`, the 10 ms free CPU limit and all front-end behaviour on real devices are unproven. The deploy plan therefore starts with a **preview deployment and a smoke test** before the real domain. *S2*
5. **The sign-in e-mail allowance.** Resend free allowance is shared; a common public link means strangers can ask for codes. Existing caps (per IP, per e-mail, per society, staff reserve) stay and are tested; the plan adds a per-list daily cap shown to the organizer. *S2*
6. **Public portal and abuse.** A public page that lists masked names must not be scrapeable into full identities: masked names, last-4 mobile only is **not** shown (only the unit and a masked name are shown), e-mail never shown. Decision recorded in the plan. *S1 for the new build*

## What stays (reused as it is)
Signed hash-chained audit log and atomic guards; OTP, sessions, rate limits, mail outbox; text cleaning, CSV/Excel import; the checks engine and fingerprint; masking; PDF/CSV export code; the dev server and the free-plan layout.

## Round 0 result
**Not a pass, and not meant to be.** Ten items above feed GAPS-AND-PLAN.md. Round 1 is the first independent audit of the rebuilt product.
